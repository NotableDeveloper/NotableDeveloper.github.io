Docker 컨테이너는 Linux 커널의 격리 기능을 활용해 프로세스와 파일, 네트워크 등의 실행 환경을 분리한다. 같은 이미지를 바탕으로 컨테이너를 만들면 개발과 운영 환경에서 실행 조건을 일관되게 맞추기 쉽다.

## 컨테이너를 사용하는 이유

- **환경 표준화**: 실행 환경을 이미지로 만들어 공유하므로 다른 운영체제나 하드웨어에서도 같은 구성을 재현하기 쉽다.
- **생산성**: 컨테이너를 빠르게 만들고 제거할 수 있으며, 이미지 계층을 재사용하고 버전을 관리할 수 있다.
- **자원 효율**: 가상 머신처럼 별도 게스트 운영체제를 포함하지 않고 호스트 커널을 공유한다. 네트워크와 파일 시스템을 분리해 관리할 수도 있다.

## 생명주기

```text
생성(create) → 실행(start) → 일시 중지(pause) → 재개(unpause)
                      │
                      ├─ 정지(stop 또는 kill) → 재시작(start)
                      └─ 정지된 뒤 제거(rm)
```

`docker create`는 컨테이너를 만들지만 시작하지 않는다. `docker start`로 실행하고, `docker pause`와 `docker unpause`로 실행을 일시 중지하거나 재개할 수 있다. `docker stop`은 정상 종료를 요청하고, `docker kill`은 프로세스에 종료 신호를 보낸다. 정지한 컨테이너는 `docker start`로 다시 시작할 수 있으며, `docker rm`으로 제거하면 컨테이너 자체가 시스템에서 사라진다.

컨테이너의 생명주기와 데이터를 분리하려면 데이터를 볼륨으로 관리한다. 컨테이너를 지워도 보존해야 할 파일을 쓰기 계층에만 남겨두지 않는다.


## 컨테이너 실행과 상태 확인

이미지에서 컨테이너를 만들고 시작한 뒤, 상태를 확인하고 정지·제거하는 기본 흐름은 다음과 같다.

```sh
docker create --name web nginx
docker start web
docker ps
docker stop web
docker rm web
```

`docker run --name web -d nginx`를 사용하면 생성과 시작을 한 번에 처리한다. 컨테이너를 제거하면 쓰기 계층의 변경도 사라지므로 필요한 파일은 볼륨에 저장한다.
