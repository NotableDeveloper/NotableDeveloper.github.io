내부 전화망의 전화기를 외부 전화망과 연결하려면 PSTN과 직접 통신하는 서버를 별도로 두는 구성이 유용하다. 5001번 전화기가 속한 서버와 7001번 전화기가 속한 서버를 유지하면서, PSTN 연동을 담당하는 Proxy 서버를 하나 더 배치한다.

~~~text
5001 전화기 ──▶ 5001 서버 ──▶ PSTN 연동 Proxy ──▶ PSTN망
7001 전화기 ──▶ 7001 서버 ──▶ PSTN 연동 Proxy ──▶ PSTN망
~~~

5001번 서버와 7001번 서버는 앞서 구성한 SIP-Trunk 환경과 같은 방식으로 준비한다. 추가되는 서버는 내부 서버의 통화를 받아 PSTN으로 전달하는 역할을 맡는다.

## 서버 사이의 계정 등록

각 서버는 통화를 전달할 상대를 PJSIP 계정으로 등록한다. 설정 위치는 /etc/asterisk/pjsip.conf이고, 방식은 Proxy 서버끼리 계정을 등록했던 과정과 같다.

다만 모든 주소를 같은 방식으로 쓰면 안 된다. 같은 사설 네트워크에 있는 서버를 등록할 때에는 사설 IP를 사용하지만, PSTN망과 연결되는 대상은 외부에서 도달할 수 있는 공인 IP를 사용해야 한다.

~~~text
5001 서버
  5001 전화기 ──▶
  7001 서버 ────▶
  PSTN 연동 Proxy (사설 IP) ──▶

7001 서버
  7001 전화기 ──▶
  5001 서버 ────▶
  PSTN 연동 Proxy (사설 IP) ──▶

PSTN 연동 Proxy
  5001 서버 ──▶
  7001 서버 ──▶
  PSTN망 (공인 IP) ──▶
~~~

## 주소를 구분해야 하는 이유

사설 IP는 해당 네트워크 안에서만 유효하다. 따라서 내부 서버끼리의 등록에는 사설 주소를 사용할 수 있지만, PSTN 사업자 또는 외부 네트워크와 통신하는 Peer 정보에는 PSTN 측과 연결된 공인 주소를 넣어야 한다.

최종적으로는 각 서버의 PJSIP 계정, 전송 주소, Dialplan이 같은 경로를 가리키는지 확인해야 한다. PSTN 연동 Proxy만 외부망을 바라보도록 역할을 분리하면 내부 전화기 설정과 외부 통신 설정을 나누어 관리할 수 있다.

## 정리

다중 Proxy 구성의 핵심은 서버를 역할별로 나누고, 상대 서버가 어느 네트워크에 있는지에 따라 등록 주소를 구분하는 것이다. 내부 서버에는 사설 IP를 등록하고, PSTN과 통신하는 Peer에는 공인 IP를 등록해야 한다. 이 기준을 지키면 기존 내부 통화를 유지하면서 외부 전화망으로 나가는 경로를 추가할 수 있다.
