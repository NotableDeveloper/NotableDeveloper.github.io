서비스를 운영하다 보면 사용자 요청을 더 처리하기 위해 애플리케이션 서버나 데이터베이스를 늘려야 한다. 물리 서버를 추가하면 비용이 들고, 서버마다 운영체제와 실행 환경을 갖추고 애플리케이션을 설치해야 한다.

가상 머신은 한 대의 물리 컴퓨터 안에 여러 가상 컴퓨터를 만들어 서버 장비 비용을 줄인다. 다만 각 가상 머신에 운영체제와 애플리케이션 환경을 설치해야 하므로 준비 작업과 시간이 여전히 필요하다.

## 가상 머신과 컨테이너의 차이

가상 머신은 하이퍼바이저 위에 게스트 운영체제를 올리고 그 위에서 애플리케이션을 실행한다. 컨테이너는 호스트 운영체제의 커널을 공유하면서 프로세스와 실행 환경을 격리한다. 그래서 컨테이너는 가상 머신보다 시작이 가볍고 빠르며, 동일한 호스트에서 더 많은 작업을 실행할 수 있다.

```text
가상 머신
물리 서버
└─ 호스트 운영체제
   └─ 하이퍼바이저
      ├─ 가상 머신 A: 게스트 OS → 런타임 → 애플리케이션
      └─ 가상 머신 B: 게스트 OS → 런타임 → 애플리케이션

컨테이너
물리 서버
└─ 호스트 운영체제와 커널
   └─ 컨테이너 런타임
      ├─ 컨테이너 A: 격리된 프로세스와 실행 환경
      └─ 컨테이너 B: 격리된 프로세스와 실행 환경
```

컨테이너는 별도의 운영체제 커널을 포함하지 않는다는 점에서 가상 머신과 다르다. 컨테이너를 사용해도 애플리케이션이 실행될 환경은 필요하지만, 게스트 운영체제 전체를 매번 설치하지 않아도 된다.

## 컨테이너와 Docker

컨테이너는 애플리케이션을 격리된 프로세스로 실행할 수 있게 하는 환경이다. 프로세스는 운영체제로부터 CPU와 메모리 같은 자원을 할당받아 작업을 수행한다. 컨테이너는 이런 프로세스와 파일 시스템, 네트워크 등의 실행 환경을 묶어 관리한다.

Docker는 컨테이너 이미지를 만들고 컨테이너를 실행하는 런타임 도구다. 이미지를 만들고 배포하는 흐름을 자동화하는 데에도 사용된다. 여러 서버에 컨테이너를 배치하고 상태를 관리하는 오케스트레이션은 Kubernetes 같은 도구가 담당한다.

```text
Dockerfile과 애플리케이션 코드
              │ 빌드
              ▼
        Docker 이미지
              │ 실행
              ▼
        Docker 컨테이너
              │ 여러 서버에서 관리
              ▼
   오케스트레이션 도구(예: Kubernetes)
```

가상 머신은 하드웨어 수준에 가까운 가상화로 독립된 운영체제를 제공하고, 컨테이너는 호스트 커널을 공유하는 프로세스 격리 방식이다. 두 기술은 목적과 격리 경계가 다르므로 상황에 맞게 선택한다.
