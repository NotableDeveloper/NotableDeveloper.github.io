Docker 이미지와 컨테이너는 개발에서 배포까지 이어지는 기본 단위다.

```text
개발자가 코드와 Dockerfile을 원격 저장소에 등록
                    │
                    ▼
          Dockerfile을 빌드해 이미지 생성
                    │
                    ▼
        Docker 엔진이 이미지에서 컨테이너 실행
```

## 이미지와 컨테이너

이미지는 컨테이너를 실행하는 데 필요한 파일과 설정을 담은 불변의 템플릿이다. 코드, 런타임, 라이브러리, 환경 변수와 설정 등이 이미지에 포함될 수 있다. 컨테이너는 이미지를 바탕으로 만들어져 실행되는 인스턴스다.

이미지는 여러 읽기 전용 계층으로 구성된다. Dockerfile의 변경이 새로운 계층으로 쌓이며, 이미지끼리 공통 계층을 공유할 수 있다. 이를 통해 중복 저장과 전송량을 줄이고 변경된 계층을 효율적으로 배포한다. 컨테이너가 실행되면 이미지 위에 쓰기 계층이 붙는다. 이 쓰기 계층의 변경은 컨테이너에 속하므로 컨테이너를 제거하기 전에 필요한 데이터를 볼륨 등으로 보존해야 한다.

```text
이미지 계층 (읽기 전용)
┌─────────────────────┐
│ 애플리케이션 계층   │
├─────────────────────┤
│ 런타임·라이브러리   │
├─────────────────────┤
│ 베이스 이미지       │
└─────────────────────┘
          │ 컨테이너 실행
          ▼
┌─────────────────────┐
│ 컨테이너 쓰기 계층  │ ← 컨테이너 생명주기에 종속
├─────────────────────┤
│ 공유 이미지 계층    │
└─────────────────────┘
```

## 이미지 조회와 관리

```sh
docker image inspect <이미지>
docker search <이름>
docker image pull <이미지[:태그]>
docker image tag <원본[:태그]> <대상[:태그]>
docker image rm <이미지>
docker image prune
```

`inspect`는 이미지의 상세 속성을 보여준다. 이미지 식별에는 태그를 사용할 수 있으며, 태그를 생략하면 기본 태그가 적용된다. 이미지의 digest는 콘텐츠를 식별하는 해시 값으로, 태그가 이동하거나 달라지는 상황에서 특정 이미지 버전을 가리키는 데 유용하다.

이미지를 제거하려면 해당 이미지에 의존하는 컨테이너 상태를 먼저 확인해야 한다. 이미지를 사용하는 컨테이너가 남아 있으면 삭제가 거부될 수 있고, 강제 삭제 옵션은 실행 중인 환경에 영향을 줄 수 있으므로 신중히 쓴다. `prune`은 사용하지 않는 이미지 정리에 활용한다.
